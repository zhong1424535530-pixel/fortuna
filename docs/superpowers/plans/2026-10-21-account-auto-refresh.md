# 账户余额自动刷新实施计划

**目标：** 保留行情每60秒更新，补上交易所余额／数量／合约每60秒、钱包主币／代币每300秒自动读取。

**方法：** 复用现有账户同步和失败保留机制。本机服务根据最近查询及成功时间判断是否到期，多个页面不能重复查询同一账户。页面统一安排余额与行情查询，避免旧行情覆盖新余额；钱包扫描超时或平台限流时允许延后。

**范围：** 不变更账户权限，不同步交易历史，不增加收费来源，不改变人工资产。

## 实施步骤

- [x] `server/connection-service.mjs`：`sync(id, force, automatic)` 增加自动模式，到期时间交易所60000毫秒／钱包300000毫秒；忙碌或未到期直接返回本机资料。连续读取失败按2／4／8倍间隔退让，最多15分钟，手动刷新不受自动退让限制。
- [x] `server/workspace-api.mjs`：沿用本机安全检查及原有同步入口，增加 `?automatic=1`，不增加外部可访问入口。
- [x] `src/data/live.ts`：补上余额自动读取与防重复；行情保留60秒计时，余额每15秒检查是否达到60秒／300秒的读取间隔，启动和切回页面补查过期账户。余额查询后继续原有行情更新；失败显示现有警告且保留数据。
- [x] `src/App.tsx` 与账户页：接入计时器，更新频率说明，保留手动刷新。
- [x] 准备隔离检查：一分钟／五分钟边界、多页面重复、失败保留、退让及恢复、忙碌不叠加、计时器清理。不接真实平台或钥匙串。
- [x] 只执行语法检查及 `npm run build`；模拟检查脚本等待用户另行同意后运行。

## 验收边界

网页关闭后不再安排新查询。1分钟／5分钟为正常情况下的目标间隔，读取耗时或上游限制可能造成延迟；成功时间必须来自余额读取，行情不能冒充余额已更新。目录外代币仍受现有扫描范围限制。
