# 全项目SQLite保存改造实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. 用户禁止未获准运行模拟或真实迁移；只准备断言，执行静态检查。当前目录不是Git仓库，不创建分支、不提交。

**Goal:** 业务资料统一长期保存，可迁移旧资料、完整备份恢复，并按需查询历史。

**Architecture:** 原保存入口统一接入本机`portfolio.sqlite`；无正式资料库时继续旧文件模式，只有单独执行并确认迁移才切换。用数据库原子写入保护多类业务资料，保留编号、金额及账户身份。历史原始点和计算依据永久归档，页面只取所需范围。

**Tech Stack:** 现有Node v25.4内置`node:sqlite`、现有Decimal与校验、React/TypeScript；不新增依赖。

## Task 1：数据库基础及安全迁移入口

- [x] 新建`server/database.mjs`：仅存在正式数据库时才启用；元数据版本、业务文档、原始交易及进度、历史曲线、账户快照及价格依据表，索引账户/时间。提供同步原子写入，错误不返回空资料。
- [x] 新建显式迁移命令：复制旧文件/素材作迁移前备份，校验四份旧业务资料，导入临时库，核对完整原始值与条数，最后原子切换并保留源文件。迁移失败保留旧入口；重复执行不重复导入。
- [x] 在新隔离检查脚本准备迁移、失败回退、金额精度、100000条以上写入断言；不运行。

## Task 2：现有四类保存接入

- [x] `server/workspace-store.mjs`保留旧人工备份导入格式、版本冲突检查；数据库启用后读写业务文档并保存修改前副本。
- [x] `server/connection-service.mjs`保存现有连接/当前快照，记录每次有效变更的历史观测；密钥仍在钥匙串。读取旧资料的校验导出供迁移工具复用。
- [x] `server/transaction-store.mjs`按原编号逐条增量写入和去重，保留关联费用去重，移除数据库总量限制而保留请求批次检查；提供账户/日期查询与列表页结果。禁止静默丢弃损坏资料。
- [x] `server/equity-history.mjs`数据库按时间保存所有有效采样；页面按范围取图形点，原始点不因旧4000点策略被清掉。

## Task 3：查询与页面接入

- [x] 交易页按来源/日期取得完整合约上下文，服务器整理列表并分页，汇总覆盖完整筛选范围。保留旧接口供自动读取/收益计算兼容，校验不以全库100000条限制替代分页。
- [x] 曲线显示抽样与原始归档分开；历史行情和奖励计价依据进入资料库。
- [x] 原始金额、隐藏金额、原账户身份和现有筛选口径保持一致；未读资料仍为缺失。

## Task 4：完整备份与恢复

- [x] 安全数据库快照、每日首次新资料后备份，最近30份日备份；迁移与恢复前额外备份。只在数据库模式启用，开发期间不创建本人资料备份。
- [x] 设置页区分旧人工备份和完整业务备份，预览业务数量后确认恢复；完整备份覆盖资料库及自定义素材，不含密钥，恢复操作必须等待查询/写入空闲。
- [x] 复用本机来源访问检查和请求大小检查，拒绝非法路径、无效库及不兼容版本。
