# 交易记录五项汇总实施计划

用户已同意本方案；代码修改与模拟测试分开。本目录无 Git 仓库，不创建分支或提交；不查询真实账户、不读取密钥、不改存量流水。

**目标：** 筛选栏下显示合约平仓盈亏、手续费支出、充值/收到、提现/转出、奖励五项紧凑汇总。

**实现：** 复用已保存流水、完整合约轮次、已有币种身份目录及十进制金额工具。仅账户和北京时间日期影响汇总，分类、搜索、状态、分页不影响。不同币种不换算，已确认身份的同币种可合并，未知同名币保留网络/地址区分。

## 范围与规则

- `src/data/transaction-summary.ts`：纯统计函数，无网络/文件读写。已完成且在区间内平仓的完整轮次累计平台盈亏，不扣手续费/资金费；费用按流水自身时间统计，含未平仓成交，避免成交费用与独立费用重复，实际发生的失败链上费用仍保留。负手续费单列返还，不抵消支出。
- 收付只计已完成；遍历全部已读历史及已添加钱包识别内部转账，即使另一侧在筛选范围外也能排除。仅在同链、已知对方地址，或同交易编号和币种数量/收款地址吻合时排除，不凭金额时间猜测。内部搬钱的真实手续费仍计入。
- 奖励以2026-10-22-reward-usdt-valuation.md的后续用户决定为准：现货返佣按记录时点市价折合USDT，稳定币1:1合并，不另列未确认明细；受限新人奖励及缺价格记录排除，原币保留，不改支付状态。
- `src/components/TransactionSummary.tsx`：五张小卡，每张最多两行金额，其余折叠；充值/收到、提现/转出分行。金额隐藏时不泄露数字或盈亏颜色。移动端横滑，避免占用多行高度。
- `src/components/TransactionsPage.tsx`：复用页面状态与已计算合约轮次，筛选栏后挂载汇总。列表和账户更新逻辑不改。
- `src/records-pages.css`：限定汇总样式，不改其他页面布局。
- `scripts/check-contract-history.mjs`：追加纯假资料断言，覆盖独立筛选、不同币种、旧奖励、未平仓费用、重复费用、失败链上实际费用、内部地址识别和跨日期配对。准备后不运行。
- `README.md`：记录统计口径及缺失数据限制。

## 已知限制

统计仅覆盖已读取记录，不保证完整历史。未能确认的自己账户间转移仍可能留在收付中；钱包非资产操作原本不采集，其费用也无法从现有流水补出。平台提现时间保留现有申请时间；实际扣费日期未单独提供时不能冒充精准扣费时刻。返佣原币种明细不代表实际到账奖励。
