# 奖励记录 Implementation Plan

> 用户已明确批准开发：统一叫“奖励”，包含现货、合约返佣及可明确识别的官方奖励。只修改代码与静态核对；模拟、浏览器验收和主动真实账户核对等待另行同意。

**Goal:** 现有交易记录增加“奖励”，全部分类也包含奖励；不另建返佣页面。

**Architecture:** 复用币安现有只读客户端、交易存储和自动更新。现货补读 `/sapi/v1/rebate/taxQuery`；合约复用 `/fapi/v1/income` 中官方明确的返佣和新人奖励。记录来源、金额和时间保留原始含义，不把资金费、交易盈亏、划转或未知正收入猜成奖励。

### 范围

- [x] 先补隔离断言：现货两类返佣、多页/空页、编号缺失时稳定去重及相同记录次数、错误/限频保留、合约奖励、非奖励不混入。保存但不执行。
- [x] `src/data/transaction-rewards.ts` 集中定义明确的合约奖励种类、旧记录兼容判断和中文说明；不按收入正负猜来源。
- [x] `src/data/transactions.ts` 增加奖励类型。现货查询仅报告检索记录而非实际到账状态，状态为已记录；时间为平台更新时间。
- [x] `server/binance-reader.mjs` 仅增加现货返佣 GET 白名单；`server/binance-transactions.mjs` 按最近7天、页码和总量完整读取，单次最多10页，失败保留旧资料；该重查询同账户每小时最多一次，合约奖励沿用原资金记录读取。无平台单笔编号时以来源、币种、类型、时间、金额及相同记录序号稳定标识。
- [x] `src/data/transaction-feed.ts` 分类增加奖励；旧合约收支中已明确的奖励也可显示；`contract-history.ts` 不把这类收入当成单笔合约盈亏或费用缺失。
- [x] `TransactionsPage.tsx` 奖励显示原金额、奖励类型、所属账户及时间；支持隐藏金额、搜索、来源与日期。奖励详情省去无关成交字段。
- [x] 更新 README 范围和官方依据；只运行 `npm run check`、`npm run build`、`node --check`，安排只读审查。

### 已确认边界

现货文档只提供币种、类型、金额、更新时间，没有到账时间或逐笔支付状态，因此不能保证与截图逐笔匹配。现货返佣不代表全部活动奖励；合约明确支持 COMMISSION_REBATE、REFERRAL_KICKBACK、API_REBATE、CONTEST_REWARD、BFUSD_REWARD、WELCOME_BONUS，其他奖励只有官方来源确认后再补。新人奖励可能有使用限制。此页流水不再次加入资产余额。
