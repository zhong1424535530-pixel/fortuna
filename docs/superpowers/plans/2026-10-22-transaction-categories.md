# 交易记录分类与统一更新 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans. 用户已明确批准本方案；代码修改与模拟测试分开，本轮不运行模拟、浏览器或真实账户查询。目录没有 Git，原地小范围修改。

**Goal:** 删除交易记录页的同步卡片；通过账户自动更新及账户卡片刷新更新交易记录，统一分类展示。

**Architecture:** 复用现有余额更新和只读交易查询。交易查询串行并复用同来源请求；自动查询币安间隔5分钟、钱包15分钟，失败退让，避免每次余额或行情更新都重扫7天。手动账户刷新等待同来源在途查询，再更新余额及交易记录。交易页仅加载本机保存资料并接收更新通知，不提供独立同步按钮。

**Tech Stack:** 现有 React、TypeScript、本机交易读取接口、decimal.js；不增加依赖。

### 文件及顺序

- [x] `src/data/transaction-client.ts`：复用同来源请求、串行读取、缓存本机结果、失败保留和通知；防止较早本机读取覆盖新查询结果。
- [x] `src/data/live.ts`：现有定时器同时检查交易记录到期时间；后台交易读取不堵住其他账户余额；手动刷新等待同来源查询，余额成功后交易失败要区分提示。
- [x] `src/data/transaction-feed.ts`：分类为全部、合约、现货、转账、充值、提现、兑换。全部汇总合约轮次与其他分类，合约逐笔成交、费用流水不重复列入。按平仓或发生时间倒序，先完整合并再筛选。
- [x] `src/components/ContractHistory.tsx`：提取现有合约卡片和详情供统一列表复用，保留金额隐藏及原始成交详情。
- [x] `src/components/TransactionsPage.tsx`：只有分类、共用搜索/来源/日期筛选和紧凑记录列表；合约状态筛选保留，默认已平仓。删除同步、补查输入、第二套筛选和全部流水开关。读取限制仅放底部折叠说明。
- [x] `src/records-pages.css`：仅补充分类和普通记录紧凑样式。
- [x] 更新 `README.md`、`scripts/check-auto-refresh.mjs`；准备分类断言及有授权后执行的命令，不运行它们。
- [x] 执行静态 `npm run check`、`npm run build`、`node --check`；安排只读代码审查。完成后询问模拟测试。

### 具体约束

```ts
// 钱包收转和自己账户划转属于转账，交易所充值/提现分别归类。
// 合约用已合并的轮次；不把持仓变动或示例资料冒充交易。
// 自动读取：同一来源未完成时复用，连续失败逐步延长到最多1小时。
// 手动账户刷新：余额已成功但交易记录失败，明确告知并保留旧交易记录。
```

自动读取仍仅限已有支持的币安和免费钱包来源。其他交易所不编造记录；不会新增密钥、付费服务或更改资产余额计算。

静态完成记录：TypeScript 检查、网页构建及两个修改的 mjs 文件语法检查通过（构建仍提示原有文件体积较大）。只读审查指出的同源重复读取、全局余额阻塞、旧快照覆盖及移除后错误残留均已修正；新增隔离断言已保存，未运行。模拟与页面验收等待用户另行授权。
